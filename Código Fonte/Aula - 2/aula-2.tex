Este documento serve como continuação do material \texttt{``aula-1.pdf''}, apresentado na primeira aula, que teve como objetivo introduzir os básicos da linguagem \TeX.

Seu objetivo é introduzir conteúdos mais avançados do \LaTeX, focando nos seguintes elementos:


\begin{itemize}
	\item Gerenciamento de Pacotes
	\item Referências Bibliográficas
	\item Formatação Avançada (ABNT, SBC)
	\item Resolvendo Problemas de Compilação

\section{Gerenciamento de Pacotes}
Antes de compreender o funcionamento de templates visuais, modelos prontos ou novas classes de documento, é fundamental revisar e expandir alguns conceitos relacionados ao gerenciamento de pacotes no \LaTeX.

De forma geral, o gerenciamento adequado de pacotes é o que permite estender as funcionalidades básicas do compilador, tornando possível a criação de documentos mais complexos, organizados e visualmente consistentes.

\subsection{Como Encontrar Pacotes?}
A forma mais confiável de encontrar pacotes para \LaTeX \hspace{1pt} é por meio do repositório oficial conhecido como CTAN, sigla para \texttt{``Comprehensive \TeX\hspace{1pt} Archive Network''}. O CTAN reúne praticamente todos os pacotes disponíveis para o ecossistema \TeX\ e \LaTeX. 

Nesse repositório, é possível encontrar descrições detalhadas dos pacotes, informações sobre compatibilidade, histórico de versões e, em muitos casos, manuais de uso e exemplos práticos. Além disso, a maioria das distribuições modernas do \LaTeX, como \TeX\ Live e MiK\TeX, utiliza o CTAN como base para instalação e atualização automática de pacotes.


\subsection{Utilizando Pacotes}
Conforme mencionado antes, não existe uma padronização na sintaxe dos pacotes no \LaTeX. Cada pacote vai adotar sua própria sintaxe ou estrutura. Alguns pacotes apenas realizam ações diretas no código fonte, sem a necessidade de novos elementos diretos, sendo presentes apenas no preâmbulo. 

Em outros casos, os pacotes podem introduzir novas funcionalidades que demandam ajustes na sintaxe padrão. Como não é possível descrever o funcionamento de todos os pacotes existentes de forma individual, esse documento irá direcionar seu foco para pacotes ``essenciais'', que cobrem funcionalidades utilizadas em grande parte dos documentos, conforme os exemplos:

\begin{itemize}
	\item Posicionamento de imagens
	\item Troca de fontes
	\item ``Pular'' linhas por padrão
\end{itemize}

\subsubsection{Posicionando Imagens}

Um dos primeiros pacotes de interesse na produção de artigos científicos é o pacote \texttt{``float''}.

Esse pacote permite um controle mais explícito sobre o posicionamento de imagens no documento, uma vez que o comando básico \texttt{\textbackslash includegraphics} delega essa tarefa automaticamente ao compilador durante o processo de compilação.

Para utilizar esse pacote, é necessário incluí-lo no preâmbulo do documento, conforme apresentado no documento \texttt{``aula-1.pdf''}:

\begin{teX}
	\usepackage{float}
\end{teX}

Após a inclusão do pacote, imagens devem ser inseridas por meio do ambiente \texttt{figure}, que é o ambiente padrão do \LaTeX\ para a inclusão de elementos gráficos:

\begin{teX}
	\begin{figure}
		\includegraphics{exemplo.jpg}
	\end{figure}
\end{teX}

Esse ambiente pode receber parâmetros adicionais que influenciam o posicionamento da imagem no documento, por meio da seguinte sintaxe:

\begin{teX}
	\begin{figure}[x]
		\includegraphics{exemplo.jpg}
	\end{figure}
\end{teX}

Nesse caso, o parâmetro \texttt{x} pode ser substituído por diferentes opções de posicionamento. As opções mais comuns são apresentadas a seguir:

\begin{itemize}
	\item \texttt{h} (\textit{here}): sugere que a imagem seja posicionada no local onde o código aparece.
	\item \texttt{t} (\textit{top}): posiciona a imagem no topo da página.
	\item \texttt{b} (\textit{bottom}): posiciona a imagem na parte inferior da página.
	\item \texttt{p} (\textit{page}): posiciona a imagem em uma página exclusiva para elementos flutuantes.
	\item \texttt{!}: parâmetro adicional que ``relaxa'' as restrições do algoritmo de posicionamento, tornando a inclusão da imagem mais flexível.
\end{itemize}

Essas opções podem ser combinadas para oferecer maior flexibilidade ao compilador. Por exemplo:

\begin{teX}
	\begin{figure}[ht]
		\centering
		\includegraphics{exemplo.jpg}
	\end{figure}
\end{teX}

Nesse caso, o \LaTeX\ tentará posicionar a imagem primeiro no local do código e, caso isso não seja possível, no topo da página. Outro elemento interessante vêm através da adição do comando \texttt{\textbackslash centering}, que centraliza a imagem presente no ambiente \texttt{figure}.

Apesar disso, nem sempre é possível posicionar uma imagem exatamente no ponto desejado do documento, devido aos mecanismos automáticos de organização do \LaTeX. Para esses casos, o pacote \texttt{float} adiciona uma nova opção de posicionamento:


\begin{itemize}
	\item \texttt{H}: força o posicionamento da imagem exatamente no local onde o código aparece, ignorando o algoritmo padrão de flutuação.
\end{itemize}

É importante ressaltar que a opção \texttt{H} não pode ser combinada com outros parâmetros e só está disponível quando o pacote \texttt{float} é utilizado.


\subsubsection{Trocando de Fontes}
O processo de troca de fontes no \LaTeX\hspace{1pt} é um pouco mais complexo no quesito de gerenciamento. Isso ocorre porque, além de muitas vezes ser necessário consultar um repositório de pacotes, fontes proprietárias (como a \textbf{Times New Roman}) não estão incluídas nativamente nas distribuições básicas por questões de licenciamento.

Um exemplo disso é a fonte ``Times New Roman'', que é uma fonte proprietária da Microsoft. Nesse caso, é preciso utilizar alguma fonte que seja equivalente, só que gratuita. Fontes semelhantes tendem a ser indistiguíveis ao olho nu, e podem ser tratadas como substitutas diretas, mas é importante saber o nome do pacote associado à essa fonte.

Apesar disso, é possível contornar esse problema mudando de compilador. Existem três principais motores de compilação:

\begin{description}
	\item[\texttt{pdfLaTeX}:] O compilador padrão em grande parte das distribuições \TeX. É muito rápido e estável, mas limitado a fontes empacotadas especificamente para ele.
	\item[\texttt{XeLaTeX} e \texttt{LuaLaTeX}:] São compiladores modernos. A grande vantagem deles é o suporte nativo a fontes do sistema através do pacote \texttt{fontspec}. Com eles, você pode usar qualquer fonte instalada no seu computador (como Arial, Helvetica ou Times New Roman) de forma direta, sem precisar de pacotes substitutos.
\end{description}

É importante notar que alguns pacotes antigos de fontes feitos para o \texttt{pdfLaTeX} podem não funcionar perfeitamente no \texttt{LuaLaTeX} e vice-versa. Por isso, ao escolher uma fonte, verifique sempre se ela é compatível com o compilador que você está utilizando no seu projeto.

Considerando todos esses elementos em potencial, para trocar uma fonte, basta realizar a inclusão de um pacote que contenha a sua fonte de escolha no preâmbulo do documento:

Para o \texttt{pdflatex}: 

\begin{teX} 
	\usepackage[T1]{fontenc} % Garante a codificacão correta de caracteres 
	\usepackage{newtxtext}% Exemplo de pacote similar ao Times New Roman para o pdflatex 
\end{teX}

Para o \texttt{XeLaTeX} ou \texttt{LuaLaTeX}:

\begin{teX} 
	\usepackage{fontspec} 
	\setmainfont{Arial} % Ao usar XeLaTeX/LuaLaTeX, você pode chamar qualquer fonte instalada no seu sistema pelo nome exato dela. 
\end{teX}

No caso do \texttt{fontspec}, a grande diferença é que não é necessário um pacote específico para cada fonte (como o \texttt{newtxtext}). Basta carregar o pacote e indicar ao \LaTeX\hspace{1pt} qual fonte do seu sistema operacional deve ser utilizada como fonte principal.

\subsubsection{Pulando linhas por padrão}
O \LaTeX\hspace{1pt} não pula linhas por padrão. Como foi mencionado no documento \texttt{aula-1.pdf}, normalmente, são usados comandos que realizam essa tarefa:

\begin{teX}
	\\ % Pula linha
	\newline % Também pula linha
\end{teX}

Para resolver esse problema, é possível importar um pacote conhecido como \texttt{parskip}. Quando ele é utilizado, as linhas são puladas naturalmente quand há um espaço em branco, da forma que o texto é escrito.

\begin{teX}
	\usepackage{parskip} % Pula linhas por padrão
\end{teX}

\section{Referências Bibliográficas}

O processo de gerenciamento de referências bibliográficas no \LaTeX\hspace{1pt} é significativamente mais organizado e estruturado do que em processadores de texto convencionais. Para fazer com que uma referência apareça em um documento, é necessário seguir três etapas fundamentais:

\begin{enumerate}
	\item Criar um arquivo BibTeX com a extensão \texttt{.bib} contendo os metadados (autor, título, ano, etc.) da obra.
	\item Configurar o documento principal e Indicar ao \LaTeX\hspace{1pt} qual o estilo da bibliografia e qual arquivo \texttt{.bib} deve ser lido.
	\item Utilizar chaves de citação diretamente no corpo do documento.
\end{enumerate}

Exemplo de entrada no arquivo .bib:
\begin{lstlisting}[style=bibtex]
	@book{lamport94,
		author    = "Leslie Lamport",
		title     = "LaTeX: A Document Preparation System",
		year      = "1994",
		publisher = "Addison-Wesley"
	}
\end{lstlisting}

Exemplo de comandos no documento principal:
\begin{teX}
	% Para citar este livro, utilizamos o comando \cite{lamport94}.
	
	% No final do documento, definimos o estilo e o arquivo:
	\bibliographystyle{plain} % Define o estilo de formatacao
	\bibliography{referencias} % Nome do seu arquivo .bib
\end{teX}

Após esses passos, a lista de referências será gerada automaticamente, geralmente em ordem alfabética, no estilo e formatação escolhidos.

\subsection{A Sintaxe do BibTeX}

Um arquivo BibTeX funciona como um repositório de metadados bibliográficos. De forma análoga a formatos como XML ou JSON, ele armazena informações estruturadas que serão interpretadas pelo compilador \LaTeX\hspace{1pt} no momento da geração das referências.
teX
Nesse contexto, o aspecto mais importante é garantir que a sintaxe do arquivo esteja de acordo com o que o BibTeX e o \LaTeX\hspace{1pt} esperam. Erros de sintaxe ou de formatação podem impedir a correta geração da bibliografia ou causar resultados inesperados.

De modo geral, a estrutura de um arquivo BibTeX segue as seguintes regras:

\begin{itemize}
	\item Cada referência é definida por uma \textit{entrada}, que sempre começa com o caractere \texttt{@}.
	\item O tipo da entrada indica a natureza da referência, como \texttt{@book} (livros), \texttt{@article} (artigos científicos) e \texttt{@misc} (materiais que não se enquadram nas categorias anteriores).
	\item Cada entrada possui um identificador único (chave), utilizado posteriormente para citar a referência no texto.
	\item Dentro de cada entrada, são definidos os campos que descrevem os metadados da referência, como \texttt{author}, \texttt{title}, \texttt{year} e \texttt{journal}.
\end{itemize}

Um exmplo desse arquivo pode ser visto abaixo:

\begin{lstlisting}[style=bibtex]
	@article{einstein1905,
		author  = "Albert Einstein",
		title   = "Does the Inertia of a Body Depend Upon Its Energy Content?",
		journal = "Annalen der Physik",
		year    = "1905",
		volume  = "18",
		pages   = "639--641"
	}
\end{lstlisting}

\textbf{Nota importante sobre autores:}  
Para que o BibTeX identifique corretamente múltiplos autores, eles devem ser separados obrigatoriamente pela palavra \texttt{and}. Por exemplo:

\begin{lstlisting}[style=bibtex]
	author = "Fulano de Tal and Beltrano de Souza"
\end{lstlisting}

O uso de vírgulas para separar autores é incorreto nesse contexto, pois o BibTeX interpreta a vírgula como parte do nome de uma única pessoa, o que pode resultar em formatação incorreta das referências.



\subsection{Referências no Padrão ABNT}

Para a utilização de referências bibliográficas no padrão ABNT, é necessário empregar um pacote ou estilo bibliográfico especificamente configurado para esse formato.

Uma das formas mais comuns de aplicar esse padrão é por meio de estilos bibliográficos compatíveis com a ABNT, que devem ser carregados no preâmbulo do documento. 

Esses estilos são responsáveis por definir a forma como as referências serão exibidas na bibliografia final.

\begin{teX}
	\usepackage[alf]{abntex2cite}
\end{teX}

\section{Formatação Avançada}

Essa parte do documento irá focar no processo de formatação de documentos \LaTeX, elaborando sobre as formatações em ABNT e SBC. 

\subsection{Formatando em ABNT}

O padrão ABNT (Associação Brasileira de Normas Técnicas) define regras específicas para a apresentação de trabalhos acadêmicos, incluindo margens, espaçamentos, fontes, títulos, citações e referências bibliográficas.

Devido à complexidade e à quantidade de normas envolvidas, não é recomendado aplicar o padrão ABNT manualmente em documentos \LaTeX. Em vez disso, a abordagem mais adequada é utilizar classes e pacotes desenvolvidos especificamente para esse fim.

\subsubsection{Classe \texttt{abntex2}}

A classe \texttt{abntex2} é a solução mais utilizada para a produção de documentos no padrão ABNT em \LaTeX. 

Ela implementa as principais normas da ABNT, permitindo que o autor foque no conteúdo do texto, e não nos detalhes de formatação. Para utilizá-la, basta substituir a classe padrão do documento no preâmbulo:

\begin{teX}
	\documentclass{abntex2}
\end{teX}


\subsubsection{Observação Importante}

A classe \texttt{abntex2} possui um conjunto amplo de comandos, ambientes e opções de configuração, cuja descrição completa não é viável em um documento introdutório ou resumido.

Para uma utilização adequada e completa da classe, é recomendada a leitura da documentação oficial, mantida pelos autores do projeto. O acesso à documentação completa em PDF está disponível no repositório deste trabalho, por meio de um link direto para a fonte original, conforme indicado no \texttt{README}.

\subsection{Formatando em SBC}

A formatação no padrão SBC utiliza um modelo distinto do formato ABNT. Nesse caso, é necessário carregar um arquivo de estilização com extensão \texttt{.sty}, fornecido pela própria Sociedade Brasileira de Computação (SBC).

Após a inclusão desse template no documento, a formatação passa a seguir automaticamente as normas e diretrizes definidas pela revista ou evento. Esse comportamento é comum na maioria das publicações científicas que utilizam \LaTeX, nas quais o estilo visual é totalmente controlado por arquivos de classe ou de estilização.

Em comparação com o modelo ABNT, o padrão SBC apresenta um processo de configuração mais simples, exigindo menos ajustes manuais por parte do autor.

\subsection{Arquivos \texttt{.sty}}

Arquivos com extensão \texttt{.sty} são conhecidos como \texttt{style files} e têm a função de definir regras de formatação, comportamento e macros adicionais para documentos \LaTeX.

Um arquivo \texttt{.sty} age como um arquivo de texto contendo comandos \LaTeX, de forma semelhante ao que é escrito diretamente no preâmbulo de um documento.

A diferença é que essas configurações ficam organizadas em um único arquivo, facilitando a padronização visual e estrutural.

Ao incluir um arquivo \texttt{.sty} em um documento, o autor delega ao template a responsabilidade pela formatação. Isso pode envolver, por exemplo:
\begin{itemize}
	\item Definição de margens e espaçamentos;
	\item Escolha de fontes e tamanhos de texto;
	\item Estilo de títulos, seções e cabeçalhos;
	\item Formatação de citações, referências e legendas;
	\item Criação de novos comandos e ambientes.	
\end{itemize}

A inclusão de um arquivo \texttt{.sty} é feita por meio do comando \texttt{\textbackslash usepackage\{\}}, desde que o arquivo esteja disponível no mesmo diretório do documento ou em um diretório conhecido pelo compilador:

\begin{teX}
	\usepackage{nomedoestilo}
\end{teX}

Não é necessário especificar a extensão \texttt{.sty}, pois o \LaTeX\hspace{1pt} identifica automaticamente o tipo do arquivo.

No contexto acadêmico, arquivos \texttt{.sty} são amplamente utilizados por revistas, congressos e instituições para garantir que todos os trabalhos submetidos sigam exatamente o mesmo padrão visual, independentemente do autor ou do editor utilizado.

O arquivo de estilização padrão para a revista SBC está disponível nesse repositório para consulta e/ou utilização.

\section{Resolvendo Problemas de Compilação}

Durante o uso do \LaTeX, é comum encontrar erros ou avisos durante o processo de compilação. Diferentemente de processadores de texto tradicionais, o \LaTeX\hspace{1pt} depende da correta interpretação do código para gerar o documento final, e pequenos erros de sintaxe podem impedir a compilação ou gerar resultados inesperados.

O objetivo dessa seção mora no desenvolvimento da habilidade investigativa e de solução de problemas quando algum erro de compilação aparecer.

\subsection{Erros e Avisos}

O compilador \LaTeX\hspace{1pt} pode emitir dois tipos principais de mensagens:

\begin{itemize}
	\item \textbf{Erros}: Interrompem o processo de compilação e podem impedir a geração do PDF. A maioria dos editores de texto irá identificar um desses momentos com uma linha vermelha. 
	\begin{itemize}
		\item Existe um cenário onde um erro pode acontecer, mas um PDF ainda pode ser gerado. Nesses casos, é possível perceber grandes problemas na formatação e/ou aparência do documento.
	\end{itemize}
	\item \textbf{Avisos} (\texttt{warnings}): Não impedem a compilação, mas indicam possíveis problemas de formatação ou inconsistências no documento.
	\begin{itemize}
		\item Um exemplo disso acontece quando as margens de um determinado documento não estão atendendo o critério do \LaTeX, ou seja, as margens foram ``relaxadas''. Isso não interfere de forma visual e direta na qualidade do documento final, sendo algo orientado à interpretação do compilador em si.
	\end{itemize}
\end{itemize}

É importante corrigir os erros assim que possível, fazer o contrário significa acumular inconsistências em um documento sem necessidade. Avisos, embora menos críticos, também merecem atenção, especialmente em documentos acadêmicos.

\subsubsection{Leitura das Mensagens de Erro}

As mensagens exibidas pelo compilador geralmente indicam:
\begin{itemize}
	\item O tipo de erro encontrado;
	\item O arquivo em que o erro ocorreu;
	\item A linha aproximada onde o problema foi detectado.
\end{itemize}

É importante observar que a linha indicada nem sempre corresponde exatamente ao local do erro, pois um problema pode ser causado por comandos mal formados em linhas anteriores.

Segue abaixo um exemplo de mensagem de erro gerada durante a compilação de um documento \LaTeX\hspace{1pt}:

\begin{lstlisting}[style=latexerror]
	! Missing } inserted.
	<inserted text> 
	}
	l.27 \section{Introdução
\end{lstlisting}

Nesse exemplo, a mensagem pode ser interpretada da seguinte forma:

\begin{itemize}
\item \texttt{Missing \} inserted}: indica que o compilador esperava encontrar uma chave de fechamento (\texttt{\}}) que não foi informada corretamente.
\item \texttt{l.27}: informa a linha aproximada onde o problema foi detectado.
\item \texttt{\textbackslash section\{Introdução}: mostra o comando que estava sendo processado no momento em que o erro ocorreu.
\end{itemize}

Embora o erro seja apontado na linha 27, o problema pode ter sido causado por uma chave aberta em uma linha anterior. Um compilador não necessariamente irá fornecer o ponto exato onde um problema aconteceu, mas uma aproximação pode ser indicada, por isso, é interessante verificar regiões próximas ao que foi indicado.


\subsubsection{Erros Comuns}

Alguns dos erros mais frequentes para usuários iniciantes incluem:

\begin{itemize}
	\item Chaves não balanceadas (\texttt{\{} sem \texttt{\}});
	\begin{itemize}
		\item Quando isso acontece, o compilador ainda pode inserir os elementos faltantes automaticamente durante compilação. Quando isso acontece, o seu editor de texto ainda pode pontuar o problema, mas o compilador do \LaTeX\hspace{1pt} irá apresentar a situação apenas como um aviso (\texttt{warning}).
	\end{itemize}
	\item Ambientes não fechados corretamente (por exemplo, \texttt{figure} sem \texttt{end});
	\begin{itemize}
		\item Esse é um caso um pouco mais crítico. Quando isso acontece, o compilador ainda consegue criar um documento em grande parte das situações, mas um erro irá ser pontuado para correção, conforme o exemplo abaixo:
		
		\begin{lstlisting}[style=latexerror]
	aula-2.tex: erro: 
	498: \begin{itemize} on input line 458 ended by \end{document}.
		\end{lstlisting}
		
		Neste caso, como não havia um ponto de fechamento para o ambiente \texttt{itemize} criado, o ambiente estava sendo fechado em \texttt{end\{document\}}. Apesar disso, um documento ainda foi gerado.
	\end{itemize}
	\item Uso de comandos matemáticos fora do modo matemático;
	\begin{itemize}
		\item Quando isso acontece, o compilador irá apresentar uma mensagem de erro, e o seu editor de texto/IDE poderá apontar o trecho em vermelho, assim como no caso de chaves não balanceadas. Apesar disso, um PDF ainda será gerado.
	\end{itemize}
	\item Inclusão de pacotes inexistentes ou não instalados;
	\begin{itemize}
	\item Este é um caso onde um documento pode não ser gerado. Quando um pacote inexistente é incluso, ou um pacote que não foi instalado é incluso, existe uma chance considerável do compilador falhar em sua tarefa, mesmo considerando as possibilidades de recuperação. 
	
	Quando isso acontece, o compilador do \LaTeX\hspace{1pt} cria uma mensagem de erro que informa a não compilação de um PDF:
	
	\begin{teX}
	\usepackage{pacoteinexistente}
	\end{teX}
	
	Durante a compilação, o \LaTeX\hspace{1pt} poderá gerar uma mensagem semelhante à seguinte:
	
	\begin{lstlisting}[style=latexerror]
	! LaTeX Error: File `pacoteinexistente.sty' not found.
		
	Type X to quit or <RETURN> to proceed,
	or enter new name. (Default extension: sty)
	\end{lstlisting}
	
	\end{itemize}
	\item Caracteres especiais não escapados, como \texttt{\_} e \texttt{\#}.
	\begin{itemize}
		\item Quando isso acontece, seu editor de texto/IDE irá marcar o ponto de falha em vermelho. A única solução para esse tipo de situação é adicionar uma \{\textbackslash\} antes de um elemento:
		
		\begin{teX}
	% Algo como:
	Um exemplo de frase com esse tipo_de_problema
	% Deve ser corrigido para:
	Um exemplo de frase com esse tipo\_de\_problema
		\end{teX}
	\end{itemize}
\end{itemize}


\subsubsection{Fontes de Consulta}

Quando um erro não pode ser resolvido facilmente, é recomendado consultar fontes externas confiáveis, como:
\begin{itemize}
	\item A documentação oficial do \LaTeX\hspace{1pt} e dos pacotes utilizados;
	\item Fóruns especializados, como \textit{TeX Stack Exchange};
	\item Exemplos funcionais fornecidos por templates oficiais.
\end{itemize}

Apesar das descrições existentes neste documento, a única forma de aprender a resolver erros de compilação de documentos em PDF utilizando o \LaTeX\hspace{1pt} é diretamente praticando a solução de problemas quando um desafio aparece.
